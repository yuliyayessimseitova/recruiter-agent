# План: ИИ-помощник рекрутера (свой сервер, РК)

## 1. Архитектура (простыми словами)
- Мозг: LLM (Claude через API) — пишет тексты, оценивает, переписывается.
- Оркестратор: Python-сервис (FastAPI) + очередь задач (Redis/Celery или просто cron + worker).
- База: PostgreSQL на сервере в РК — вакансии, кандидаты, переписка, статусы, журнал действий.
- Каналы: Telegram-бот (кандидаты и рекрутер), email, формы заявки, площадки публикации.
- Панель рекрутера: Telegram-бот или Google Sheets/Metabase для аналитики.
- Сервер: VPS у казахстанского провайдера (ps.kz, hoster.kz, Kaz.Cloud и т.п.), Ubuntu, Docker, nginx, HTTPS.

## 2. Что автоматизировать (по убыванию экономии времени)
1. Заявка от нанимающего менеджера -> уточняющие вопросы -> продающее описание вакансии (несколько вариантов под площадки).
2. Первичный скрининг: ответы на вопросы кандидатов, сбор анкеты, оценка соответствия по критериям, краткое резюме по каждому.
3. Сводная таблица откликов + дашборд: источник, воронка, время до закрытия, стоимость найма.
4. Назначение собеседований: слоты, приглашения, напоминания кандидату и интервьюеру, переносы.
5. Тестовые задания под вакансию + проверка по критериям (решение принимает человек).
6. Оферты по шаблону, согласование, письма-отказы с обратной связью.
7. Поиск пассивных кандидатов (только по публичным данным и в рамках правил площадок).
8. Прочее: база талантов с повторным контактом, онбординг-чек-лист, опрос кандидатов после процесса, еженедельный отчёт для руководства, проверка описания на дискриминационные формулировки.

## 3. Площадки: реальность интеграций
- Telegram (каналы, группы): Bot API, публикация проще всего. Начинать здесь.
- HH (hh.kz): есть официальный API, но публикация вакансий и доступ к откликам требуют аккаунта работодателя и одобрения приложения. Проверить условия.
- LinkedIn: публикация вакансий через API доступна только партнёрам; на старте — черновик + публикация вручную или через платный ATS/партнёра.
- Facebook/Instagram: Graph API (бизнес-аккаунт, страница, проверка приложения Meta). Публикация постов возможна, отклики собирать лучше через форму/Telegram-бота.
- Принцип: не парсить площадки и не обходить защиту — это нарушает правила и ведёт к блокировке аккаунтов.
- Отклики из всех соцсетей направляйте в единую форму/бота — так проще собирать согласие и вести таблицу.

## 4. Персональные данные по законодательству РК (проверить с юристом)
Основа: Закон РК «О персональных данных и их защите» от 21.05.2013 № 94-V и подзаконные акты.
- Согласие кандидата на сбор и обработку: получать до сбора анкеты (чекбокс + запись факта, времени, текста согласия).
- Цели и сроки: хранить только нужное; после закрытия вакансии удалять или спрашивать согласие на базу талантов.
- Хранение: базы с персональными данными граждан РК держать на серверах в РК. Это ключевое требование к выбору сервера.
- Трансграничная передача: отправка резюме в зарубежный LLM-API — это передача за границу. Решения: обезличивать данные перед отправкой (убирать ФИО, телефон, email, ИИН, адрес), заключить нужные соглашения/получить согласие либо использовать модель, развёрнутую на своём сервере. Выбор — с юристом.
- ИИН, документы, медданные, фото — не собирать на этапе скрининга.
- Права кандидата: доступ, исправление, удаление по запросу — предусмотреть команду «удалить мои данные».
- Решения без человека: ИИ даёт рекомендацию, отказ и оффер утверждает рекрутёр.
- Безопасность: шифрование диска и бэкапов, HTTPS, роли и доступы, 2FA, журнал доступа, секреты в переменных окружения, регулярные бэкапы с проверкой восстановления, обновления.
- Назначить ответственного за защиту ПД, оформить политику обработки ПД и опубликовать её.
- Следить за актуальными нормами по ИИ и ПД в РК — законодательство меняется.

## 5. Дорожная карта
- Этап 0 (1 неделя): процесс рекрутера на бумаге, шаблоны вакансий/офферов/тестов, критерии оценки, юридическая консультация, выбор сервера в РК.
- Этап 1 (2 недели): сервер, БД, Telegram-бот: заявка -> описание вакансии -> утверждение рекрутёром -> публикация в Telegram.
- Этап 2 (2 недели): форма/бот для кандидатов с согласием, таблица откликов, базовая аналитика.
- Этап 3 (2–3 недели): скрининг-диалог, оценка, приглашения, календарь.
- Этап 4: тестовые задания, оферты, интеграции HH/Meta/LinkedIn по мере одобрения доступов.
- Этап 5: отчёты, база талантов, улучшения по обратной связи.
Всегда: человек утверждает публикации, отказы и офферы; пилот на 1–2 вакансиях.

## 6. Что нужно от вас
- Сервер в РК (VPS 2–4 CPU, 4–8 ГБ RAM), домен.
- Аккаунты: бот Telegram, аккаунт работодателя HH, страницы Meta, LinkedIn.
- Ключ Claude API (в закрытом хранилище, не в чате).
- Примеры 3–5 вакансий, офферов и тестов компании.

## 7. Стек
Python 3.12, FastAPI, PostgreSQL, Redis, Docker Compose, aiogram (Telegram), Anthropic SDK, Metabase/Google Sheets, Caddy/nginx, Restic/pg_dump для бэкапов.
